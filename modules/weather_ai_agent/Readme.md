# Weather AI Agent POC

This module contains a CrewAI-based weather agent that uses a configured LLM to produce a natural-language weather response. It can use Gemini or a local Ollama model.

## Can This Use An LLM?

Yes, but with one important constraint: the LLM should not be the source of live weather facts. LLMs do not reliably know current weather unless they are connected to a tool or API.

This POC uses this flow:

1. Fetch current weather observations using the existing weather lookup service.
2. Pass those observations to a CrewAI agent backed by Gemini.
3. Ask Gemini to generate a concise weather summary using only the supplied observations.

## Configuration

### Use Local Ollama

Start Ollama and make sure the model is available:

```powershell
ollama list
```

Configure this module to use Ollama:

```powershell
$env:LLM_PROVIDER="ollama"
$env:OLLAMA_MODEL="gemma4:latest"
$env:OLLAMA_BASE_URL="http://127.0.0.1:11434"
```

Use the raw Ollama model name, for example `gemma4:latest`, not `ollama/gemma4:latest`.

### Use Gemini

Set your Gemini API key before running the AI agent:

```powershell
$env:LLM_PROVIDER="gemini"
$env:GEMINI_API_KEY="your-gemini-api-key"
```

Optional model override:

```powershell
$env:GEMINI_MODEL="gemini-2.5-flash"
```

The Gemini model defaults to:

```text
gemini-2.5-flash
```

## Run

From the project root, install dependencies if needed:

```powershell
.\.venv\Scripts\python.exe -m pip install -e .
```

Default location:

```powershell
.\.venv\Scripts\python.exe -m modules.weather_ai_agent.cli
```

Custom location:

```powershell
.\.venv\Scripts\python.exe -m modules.weather_ai_agent.cli --city Dallas --state TX --country US
```

Verbose CrewAI execution:

```powershell
.\.venv\Scripts\python.exe -m modules.weather_ai_agent.cli --city Dallas --state TX --country US --verbose
```

## Run The Web Interface

```powershell
.\.venv\Scripts\python.exe -m uvicorn modules.weather_ai_agent.api:app --reload --port 8002
```

Open:

```text
http://127.0.0.1:8002
```

JSON API:

```powershell
Invoke-RestMethod "http://127.0.0.1:8002/api/weather?city=Atlanta&state=GA&country=US"
```

## Expected Behavior

If `GEMINI_API_KEY` is missing, the CLI will stop with a clear configuration error.

When configured, it will:

1. Retrieve current weather details.
2. Send those details to the Gemini-backed CrewAI agent.
3. Print the AI-generated weather summary.

## Notes

- This is different from `modules/weather_agent`, which is deterministic and does not use an LLM.
- This module requires a configured LLM because the final response is generated by the model.
- The weather facts still come from the weather lookup service so the agent does not hallucinate live conditions.
