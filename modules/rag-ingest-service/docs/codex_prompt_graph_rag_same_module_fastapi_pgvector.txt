Graph RAG indexing pipeline:
After shared ingestion steps and chunking, Graph RAG indexing should:

1. Read chunks for the current resource/job.
2. Send each chunk to local Ollama/Mistral for entity extraction.
3. Send each chunk plus that chunk's extracted entities to local Ollama/Mistral for relationship extraction.
4. Normalize entity names.
5. Deduplicate and consolidate entities across the resource.
6. Run resource-level consolidation over compact extracted graph facts, not the full file or all chunk text.
7. Merge/strengthen repeated relationships across chunks.
8. Store canonical entities and relationships while preserving chunk traceability.
9. Create resource-level graph summaries.
10. Create simple communities/clusters if reasonable for the POC.

Do not send the full source file or all chunk text in one request to local Mistral.
The existing application chunking service creates chunks.
Mistral does not create chunks; it extracts structured graph facts from existing chunks.

Keep Graph RAG simple and modular.
Do not over-engineer graph algorithms.
Do not add heavy external graph databases.
Do not add Neo4j for this POC.
Use PostgreSQL tables only.
