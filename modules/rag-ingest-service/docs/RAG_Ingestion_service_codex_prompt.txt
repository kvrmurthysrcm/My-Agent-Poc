docs/RAG_Ingest_Service_Action_Plan_v1_1_Updated.docx

Goal:
Maintain and incrementally harden the existing /rag/ingest POC based on the reference document.

Current production-hardening baseline already implemented:

* Default embedding path is Ollama nomic-embed-text with EMBEDDING_DIMENSION=768.
* Embedding model registry validates supported OpenAI/Ollama embedding models at startup and in EmbeddingProviderFactory.
* Registry implementation lives in app/services/embedding_model_registry.py, with app/core/embedding_models.py kept as a compatibility import wrapper.
* If EMBEDDING_DIMENSION is not supplied, settings derive it from the embedding model registry.
* Chat/generation models such as mistral:latest, gemma4, llama*, and qwen chat models are rejected as EMBEDDING_MODEL values.
* OpenAI fake embeddings are disabled by default using ALLOW_FAKE_EMBEDDINGS=false.
* OPENAI_API_KEY is required for OpenAI embeddings unless ALLOW_FAKE_EMBEDDINGS=true is explicitly set for tests/local development.
* Runtime embedding validation checks vector count equals chunk count and every vector length equals EMBEDDING_DIMENSION.
* PostgreSQL embedding storage uses pgvector-compatible SQLAlchemy mapping.
* PostgreSQL schema is aligned to vector(768) for the local nomic-embed-text default.
* Uploads are first written under unique storage/tmp/{upload_id}/ folders, then moved under storage/resources/{resource_id}/ after resource creation.
* Ingestion fails instead of marking READY when extracted text is empty, zero chunks are created, zero embeddings are returned, embedding count mismatches, or dimensions mismatch.
* Processing failures are recorded in rag_processing_errors.
* Resource status is only set to READY after chunks and embeddings are successfully stored.
* DB worker job claiming supports PostgreSQL FOR UPDATE SKIP LOCKED and worker_id, locked_at, heartbeat_at, retry_count, max_retries, and next_retry_at fields.
* DB worker can run continuously with python -m app.workers.rag_ingestion_worker, or run one polling batch with --once.
* Legacy worker.py delegates to app.workers.rag_ingestion_worker in --once mode for one-batch local runs.
* Local/dev PostgreSQL API startup runs Alembic upgrade head automatically when AUTO_MIGRATE_ON_STARTUP=true.
* AUTO_CREATE_TABLES=false is the default; production startup must rely on Alembic migrations, not Base.metadata.create_all.
* /ready checks DB connectivity and embedding provider configuration without making expensive embedding API calls.
* Chunking preserves page_start/page_end from parser-emitted markers such as [Page 1] where possible.
* README.md, .env.example, Alembic migrations, tests, pyproject.toml, requirements.txt, and uv.lock have been updated for this baseline.
* README.md documents API startup, DB worker startup, --once mode, embedding configuration, and test execution.
