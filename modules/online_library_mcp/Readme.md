# Online Library MCP Server

MCP Streamable HTTP server that exposes tools on top of the `modules.online_library` REST API.

## Run The Online Library API First

```powershell
.\.venv\Scripts\python.exe -m uvicorn modules.online_library.api:app --reload --port 8003
```

## Run The MCP Server

```powershell
.\.venv\Scripts\python.exe -m modules.online_library_mcp.server
```

MCP endpoint:

```text
http://127.0.0.1:8004/mcp
```

## Test With MCP Inspector

MCP Inspector is the easiest manual test tool for this server. It gives a browser UI where you can initialize the MCP session, list tools, call tools, and inspect responses.

Start the inspector:

```powershell
npx @modelcontextprotocol/inspector
```

When the inspector starts, it prints a browser URL that includes an `MCP_PROXY_AUTH_TOKEN` query parameter. Open that printed URL in the browser.

Example:

```text
http://localhost:6274/?MCP_PROXY_AUTH_TOKEN=4441db2950d6b7f6db101ca4360a339f8b29df74f86afe95c832cf4f8fd5b3b1
```

The token value is generated by the inspector, so use the URL printed in your own terminal session.

In the inspector UI, use these connection settings:

```text
URL: http://localhost:8004/mcp
Transport Type: Streamable HTTP
Connection Type: Via Proxy
```

After connecting:

1. Initialize the session.
2. List tools.
3. Select a tool such as `get_resources`.
4. Use input like:

```json
{
  "limit": 1,
  "offset": 0
}
```

## Tools

The MCP server exposes all 13 non-empty Online Library table endpoints as tools:

- `get_authors`
- `get_categories`
- `get_library_users`
- `get_reading_progress`
- `get_resource_authors`
- `get_resource_tags`
- `get_resources`
- `get_subscription_rules`
- `get_subscription_tiers`
- `get_tags`
- `get_user_approval_requests`
- `get_user_bookshelf`
- `get_user_subscriptions`

It also exposes:

- `list_available_tables`

All table tools accept:

```text
limit: 1-100, default 20
offset: 0 or greater, default 0
```

## How An Agent Finds The Right Tool

An MCP client or agent does not guess REST endpoints directly. It first asks the MCP server for tool metadata by calling:

```text
tools/list
```

The MCP server returns each tool with:

- tool name
- tool description
- input schema

In this module, FastMCP builds that metadata from the Python functions in `tools.py`:

- The function name becomes the MCP tool name, for example `get_library_users`.
- The function docstring becomes the tool description shown to the agent.
- The typed function parameters become the input schema, for example `limit: int` and `offset: int`.

Example:

```python
@mcp.tool()
async def get_library_users(limit: int = 20, offset: int = 0) -> dict[str, Any]:
    """List library users, members, patrons, and account records..."""
```

When the user asks:

```text
List users.
```

The agent sees the tool metadata from `tools/list`, matches the request to `get_library_users`, and then calls:

```text
tools/call -> get_library_users
```

The tool descriptions intentionally include common business words such as users, members, patrons, books, resources, categories, tags, subscriptions, and approvals. This makes it easier for the agent to select the correct tool from natural-language user input.

## Transport

This module uses MCP Streamable HTTP:

```python
mcp.run(transport="streamable-http")
```

It uses:

```python
FastMCP(..., stateless_http=True, json_response=True)
```

This avoids the older HTTP+SSE transport.
