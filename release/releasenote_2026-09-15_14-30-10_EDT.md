# Secure API Runtime Image Optimization

- Date: 2026-09-15
- Time: 14:30:10 EDT (UTC-04:00)
- Purpose: remove test-only dependencies from the Secure API production container while preserving its Jenkins test gate and selective CI/CD behavior.
- Scope: Secure API Docker image and CI/CD change detection

## Updates

### Removed pytest from the production dependency set

`pytest>=9.0.2` was removed from `modules/secure_api/requirements.txt`. That requirements file is installed in the shared Docker base stage inherited by the runtime image, so keeping pytest there caused the production container to include the pytest framework and its transitive packages even though they are never needed while serving API traffic.

The runtime image continues to contain all application requirements: FastAPI, Uvicorn, Pydantic settings, dotenv support, multipart handling, HTTPX, Psycopg, and PyJWT cryptography support.

### Preserved test execution in the Docker test stage

The Secure API Dockerfile now installs `pytest>=9.0.2` only after entering the `test` stage. Jenkins still builds that target and runs the same test command:

```text
python -m pytest -q --junitxml=/tmp/test-results/pytest.xml
```

Tests therefore remain a mandatory deployment gate. If installation or testing fails, the parallel build coordinator returns a failure and no deployment phase begins.

### Prevented release notes from triggering a full rebuild

The selective-change detector now treats Markdown files under `release/` as documentation, matching the existing treatment of `docs/`. Without this rule, adding this release note would be classified as an unknown shared change and unnecessarily select all ten services.

When this overlay is committed, the Secure API source changes select only the `secure` service. The release note itself does not expand that selection. A commit containing only release-note Markdown will perform a documentation-only no-op build.

## Expected effect

- The Secure API runtime image no longer ships pytest or packages needed only by pytest.
- Runtime attack surface and stored image content are reduced modestly.
- Secure API test coverage and JUnit reporting remain unchanged.
- Docker dependency caching remains effective because requirements are still copied before application source.
- The normal three-runtime-image retention policy remains unchanged.
- No application source, Kubernetes manifest, endpoint, port, environment variable, or deployment dependency was changed.

## Validation checklist

- Confirm `pytest` is absent from `modules/secure_api/requirements.txt`.
- Confirm the Docker `test` stage explicitly installs pytest.
- Confirm the Docker `runtime` stage inherits application dependencies without inheriting the test-stage layer.
- Confirm the CI change detector classifies `release/*.md` as documentation.
- Run the Secure API Jenkins test target and verify all tests pass before deployment.
- After deployment, optionally compare image sizes with `docker image inspect secure-api:<tag> --format '{{.Size}}'`.

## Rollback

If rollback is required, restore `pytest>=9.0.2` to `modules/secure_api/requirements.txt` and remove the test-stage pytest installation line from its Dockerfile. The change-detection documentation rule can remain because it is independent of the image optimization.
