# Release Note: Sonar Scanner Workspace and Cache Permission Fix

**Date and time:** 2026-09-15 22:47:21 EDT (UTC-04:00)  
**Purpose:** Correct the first Online Library advisory SonarQube run, which could not write its analyzer cache and did not discover the module's `sonar-project.properties`.  
**Observed build:** Jenkins build 35, commit `17f39e6`.

## Observed Failure

The scanner image downloaded successfully, Jenkins injected the configured token, and the scanner container reached its startup code. It then stopped before contacting SonarQube with:

```text
Unable to create directory: /opt/sonar-scanner/.sonar/cache
Caused by: java.nio.file.AccessDeniedException
```

The same output also reported:

```text
Project root configuration file: NONE
```

These messages identify two local scanner-container preparation problems. They are not SonarQube authentication, PostgreSQL, Docker network, application source, test, or Kubernetes failures.

## Root Cause

The first implementation mounted a persistent cache volume and removed all Linux capabilities from the scanner container while overriding its runtime user. The resulting user/permission combination could not initialize the mounted cache directory.

The repository was copied into a stopped container. Although the Docker copy command returned success, the subsequent scanner did not see `modules/online_library/sonar-project.properties` through the temporary mounted workspace.

## Fix

Updated `scripts/ci/sonar-online-library.sh` to use two short-lived containers with distinct responsibilities:

1. A preparation container starts with the temporary workspace and persistent cache volumes mounted.
2. Jenkins copies the checked-out repository into the running preparation container, ensuring the files are written into the mounted workspace volume.
3. The preparation container assigns the repository and cache to UID/GID `1000`, the official SonarScanner image user.
4. The preparation container is removed.
5. The actual scanner container starts as the image's non-root user, with all Linux capabilities dropped and `no-new-privileges` enabled.
6. The scanner uses the prepared workspace, detects `sonar-project.properties`, and reuses the persistent analyzer cache.
7. Cleanup removes both temporary containers and the per-build workspace volume. The shared analyzer cache remains for subsequent scans.

## Pipeline Behavior

No Jenkinsfile change is required. The Sonar stage remains advisory:

- Sonar failure is reported as an unstable stage.
- Application build, test, deployment, and stack verification continue.
- The overall build is not failed solely by SonarQube.
- The scanner log and summary remain archived.

## Expected Next-Run Evidence

The scanner output should now include the module configuration file rather than `NONE`, followed by connection and analysis activity. The terminal result will be one of:

```text
SONAR/RESULT: PASSED
```

or:

```text
SONAR/RESULT: ATTENTION_REQUIRED
```

An `ATTENTION_REQUIRED` result after this fix should be evaluated from its new message; it could legitimately represent token permissions, server compatibility, or a Quality Gate result rather than the corrected filesystem issue.

## Validation and Safety

- The application code, dependencies, Dockerfiles, Kubernetes manifests, and Jenkins orchestration are unchanged.
- No Sonar token or administrator password is stored in the overlay.
- The scanner does not receive the Docker socket, Jenkins home, Jenkins credentials, or arbitrary host mounts.
- The long-running analysis container uses the official non-root scanner user.
- Temporary resources are removed by an exit trap after success or failure.
- The persistent `sonar-scanner-cache` volume is intentionally retained to reduce future analysis time.

## Industry-Standard Position

Running the scanner as a non-root user, granting write access only to its workspace/cache, using an expiring project-scoped token, and keeping the initial Quality Gate advisory are aligned with common CI security and rollout practices. After several stable scans and an agreed new-code baseline, the Quality Gate can be made blocking.
