============================================================
SYSTEM GOAL
===========

The wrapper service should authenticate users against Keycloak.

The wrapper application should expose:

POST /auth/login

This endpoint accepts username/password from the client, calls the Keycloak token endpoint, and returns the Keycloak access token and refresh token.

After successful login, the client will call wrapper APIs using:

Authorization: Bearer <Keycloak JWT>

The wrapper service must validate JWT locally using Keycloak JWKS/certs.

After JWT validation, the wrapper service must call existing downstream FastAPI services using an internal API key.

The wrapper service must not forward the user JWT to downstream services.

Security rule:

External client to wrapper:

Authorization: Bearer <Keycloak JWT>

Wrapper to downstream FastAPI services:

X-API-Key: <internal-api-key>
X-User-Id: <Keycloak subject>
X-Username: <Keycloak preferred username>
X-User-Roles: <comma-separated roles>

Never send this downstream:

Authorization: Bearer <Keycloak JWT>

============================================================
JWT VALIDATOR
=============

Create app/auth/jwt_validator.py.

Implement class JWTValidator.

Requirements:

* Fetch JWKS from KEYCLOAK_JWKS_URL.
* Cache JWKS in memory.
* Use kid from JWT header to select the right public key.
* Validate JWT signature using RS256.
* Validate issuer using KEYCLOAK_ISSUER.
* Validate expiration.
* Audience validation should be configurable.
* TOKEN_AUDIENCE_VALIDATION_ENABLED defaults to false for this POC.
* If kid is not found, refresh JWKS once and retry.
* If still not found, return 401.
* If JWKS fetch fails, return 503.
* Use python-jose.
* Do not use token introspection for every request.

Important:
For Keycloak access tokens, audience may not equal client ID unless a proper audience mapper is configured. Therefore, for this POC, audience validation should default to false. Document how to enable it later.
