Use this login command pattern:

docker exec -it $KEYCLOAK_CONTAINER /opt/keycloak/bin/kcadm.sh config credentials `  --server $KEYCLOAK_INTERNAL_URL`
--realm $KEYCLOAK_ADMIN_REALM `  --user $KEYCLOAK_ADMIN_USER`
--password $KEYCLOAK_ADMIN_PASSWORD

Create realm:

docker exec -it $KEYCLOAK_CONTAINER /opt/keycloak/bin/kcadm.sh create realms `  -s realm=$APP_REALM`
-s enabled=true

Create roles:

Create confidential client:

docker exec -it $KEYCLOAK_CONTAINER /opt/keycloak/bin/kcadm.sh create clients `  -r $APP_REALM`
-s clientId=$CLIENT_ID `  -s enabled=true`
-s protocol=openid-connect `  -s publicClient=false`
-s serviceAccountsEnabled=false `  -s standardFlowEnabled=true`
-s directAccessGrantsEnabled=true `  -s authorizationServicesEnabled=false`
-s 'redirectUris=["http://localhost:8010/*","http://localhost:8010/docs/oauth2-redirect"]' `
-s 'webOrigins=["http://localhost:8010","http://localhost:3000","http://localhost:4200"]'

Get client UUID:

$CLIENT_UUID = docker exec $KEYCLOAK_CONTAINER /opt/keycloak/bin/kcadm.sh get clients `  -r $APP_REALM`
-q clientId=$CLIENT_ID `  --fields id`
--format csv `
--noquotes

Set client secret:

docker exec -it $KEYCLOAK_CONTAINER /opt/keycloak/bin/kcadm.sh update clients/$CLIENT_UUID `  -r $APP_REALM`
-s secret=$CLIENT_SECRET

Token verification from host PowerShell must use port 8080:

$tokenResponse = Invoke-RestMethod `  -Method Post`
-Uri "http://localhost:8080/realms/poc-realm/protocol/openid-connect/token" `  -ContentType "application/x-www-form-urlencoded"`
-Body @{
grant_type = "password"
client_id = "fastapi-auth-gateway"
client_secret = "fastapi-auth-gateway-secret"
username = "raguser"
password = "raguser123"
scope = "openid profile email"
}

Do not print the full token by default.

The FastAPI wrapper service should expose:

POST http://localhost:8010/auth/login

Example request:

{
"username": "raguser",
"password": "raguser123"
}

The wrapper internally calls:

POST http://localhost:8080/realms/poc-realm/protocol/openid-connect/token

After successful login, wrapper returns:

* access_token
* refresh_token
* expires_in
* refresh_expires_in
* token_type

Then user calls protected APIs:

GET http://localhost:8010/auth/me
Authorization: Bearer <access_token>

POST http://localhost:8010/rag/search
Authorization: Bearer <access_token>
Content-Type: application/json

{
"query": "explain graph rag search",
"top_k": 5
}

Wrapper validates JWT using:

http://localhost:8080/realms/poc-realm/protocol/openid-connect/certs

Wrapper then calls downstream RAG services using API key, not JWT:

rag-ingest-service:
http://localhost:8000/rag/ingest

rag-search-service:
http://localhost:8001/rag/search

rag-answer-service:
http://localhost:8002/rag/ask

Internal downstream headers:

X-API-Key: local-poc-internal-api-key
X-User-Id: <Keycloak subject>
X-Username: <Keycloak preferred username>
X-User-Roles: <comma-separated roles>

Never forward:

Authorization: Bearer <JWT>

to downstream services.
